# potato-vision

감자·돌 탐지, 영상 추적·계수, 공개 데이터 라벨 보정과 결함 검사 연구를 위한
코드 및 검증 기록이다. 기존 워크스페이스의 기능별 스냅샷을 보관한다.

## 현재 상태

기준일: 2026-11-10.

- 과제 A: 감자/돌 탐지 모델의 기존 자료 평가 완료. 두 모델 × 세 분할의 AP
  6개와 오류 39건 분석을 독립 검증했다.
- 현재 모델이 모든 지표에서 개선된 것은 아니다. 내부 감자 AP는 개선됐지만
  돌 AP50:95와 외부 감자 AP는 비교 모델보다 낮았다.
- 과제 B: 녹변·발아·부패·손상 다중라벨 정책만 정의했다. 모델은 아직
  학습·평가하지 않았다.
- 공개 라벨 보정: 원래 계획 23개 중 7개 완료. SAM 품질 기준과 원본 참조
  관문을 통과하지 못해 중단됐다. 2,060장 수정본이 완성된 상태가 아니다.
- 신규 촬영 세션 평가: 자료·출처·정답 미확보로 보류 중이다. 이것은 기존
  공개 라벨 수정의 중단 사유와 별개다.

## 코드 구성

| 경로 | 역할 |
|---|---|
| `scripts/`, `baseline/` | 최초 감자 탐지·영상 프레임 추출·평가 |
| `stone_experiment/` | 감자/돌 데이터 구성, 학습, 비교 평가 |
| `retraining_data/` | 검수 후보를 반영한 재학습 데이터 구성·검증 |
| `postprocess_review/` | 후처리 조건 검토와 시각 검수 자료 생성 |
| `retraining_experiment/` | 재학습·선택·평가·영상 추론 |
| `tracking_experiment/` | 캐시 기반 추적·라인 통과 계수 |
| `public_label_rework/` | 공개 라벨 입출력·보호·보정·검수·패키징 |

각 기능의 구현과 관련 스모크 검사는 같은 커밋에 포함한다. 일부 공용 모듈의
의존성 때문에 학습과 평가를 같은 기능 묶음으로 보관한다.

## 환경과 실행

Python 3.12를 사용한다. 기록된 직접 의존성은 `baseline/requirements.txt`,
CUDA 설치 구분과 기존 실행 방법은 각 기능의 README에 있다. 이 저장소의
커밋 작업에서는 패키지를 설치하거나 모델 학습·추론을 다시 실행하지 않는다.

기존 작업 환경의 인터프리터:

```sh
PY=/home/sc/.cache/potato-baseline/.venv/bin/python
```

다른 환경에서는 해당 경로를 자신의 Python 3.12 가상환경으로 바꿔야 한다.
기존 README의 절대 경로와 실행 영수증은 당시 환경의 기록이며, 모든
환경에서 그대로 실행 가능하다는 의미가 아니다.

## Git에 포함하지 않는 자료

원본 영상·사진·ZIP, 모델 가중치, 실제 데이터셋 라벨, 캐시, 대량 렌더,
학습/추론 출력과 에이전트 실행 상태는 기본적으로 제외한다. `.gitignore`는
소스·문서 중심 허용 목록이며 별도 검토한 최종 계획·수치 보고서만 명시적으로
추가한다. 제외는 파일 삭제가 아니다.

따라서 새 clone만으로 전체 실험이나 데이터 의존 스모크를 재현할 수는 없다.
기존 실험을 재현하려면 원본 자료와 가중치를 별도 보관소에서 복원하고,
각 실험의 매니페스트·해시·설정과 일치하는지 확인해야 한다. 저장된 보고서의
로컬 이미지·로그 경로는 Git에서 제외된 증거를 참조할 수 있다.

## 검증 범위

CPU 합성 픽스처 검사는 실제 원본이 없어도 가능한 항목과 실제 데이터가
필요한 항목을 구분한다. `retraining_data.smoke`, `stone_experiment.smoke`,
`retraining_experiment.smoke` 등은 기존 자료를 요구한다. 모든 검사가
독립적인 무자료 단위 테스트인 것은 아니다.

원래 `public_label_rework.protect verify`는 Git 도입 이전 파일 목록과 새 파일까지
비교하는 역사적 보호 검사다. 새 `.git/`과 저장소 문서는 승인된 추가 항목이며,
그 이전 스냅샷을 덮어쓰거나 변경을 숨기도록 보호 코드를 완화하지 않는다.
Git 도입 검증에서는 기존 파일의 바이트 보존과 승인된 신규 파일을 구분한다.

성능표는 기존 동일 장면의 시간 분할과 이미 열람한 외부 자료에 대한 결과다.
새 촬영 환경의 일반화, 전문가 정답, 배포 준비 완료를 뜻하지 않는다.
